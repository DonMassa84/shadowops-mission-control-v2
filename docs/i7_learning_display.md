# i7 learning and personal execution display

The Phoenix-native display remains `GET /display/i7`. Its six verified ShadowOps system slides still read `config/learning_focus.yaml`; their content and system meaning are unchanged. The separate canonical personal execution pool is read from `config/strategy_slides.yaml`. No strategy text is hardcoded in HEEx or JavaScript.

The strategy loader accepts only allowlisted, symlink-confined configuration paths. It validates unique IDs, non-empty titles, one or two message lines, the category/context enums, positive integer weights, non-negative cooldowns and `P0|P1|P2` priorities. Invalid individual records are skipped and reported as metadata. A missing or wholly malformed strategy file yields `STRATEGY_CONTENT=UNAVAILABLE`, while the six system slides keep `/display/i7` available. A missing primary learning plan uses `config/i7_system_fallback.yaml`, which is a YAML snapshot of the same verified six system slides. No replacement strategy content is generated.

Client rotation uses five weighted strategy selections followed by the next system slide. Category weights are CORE 40, SELF_CONTROL 15, SOCIAL_STRATEGY 10, CAREER_IHK 15, TECHNICAL 15 and REVIEW 5. Per-slide weight, explicit `active_context`, cooldown and Europe/Berlin local time adjust selection. After 22:30, weighting favors self-control, review and the four specified calibration CORE slides while reducing—but never disabling—career and technical reminders. The display never infers emotions or context from behavior, messages or surveillance.

Right/Left navigate history, Space pauses or resumes, S jumps to the next system slide, C cycles the explicit safe context list and R resumes weighted selection. The 12-second cadence, 800 ms fade, continuous ticker, 60-second live API refresh and slow burn-in movement remain intact. Strategy screens show only category, title, at most two message lines and `STRATEGY X / 72`; no progress is inferred.
