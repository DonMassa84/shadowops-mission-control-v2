## Root Causes Identified

### 1. Ollama Port Mismatch (CRITICAL) - FIXED
- **Problem**: Multiple conflicting configurations for Ollama port
  - User .bashrc: `OLLAMA_HOST=0.0.0.0:11434`
  - Systemd drop-in shadow-i7.conf: `OLLAMA_HOST=127.0.0.1:11434`
  - Systemd drop-in nemo-gpu.conf: `OLLAMA_HOST=0.0.0.0:11434`
  - Systemd drop-in 90-env.conf: `OLLAMA_HOST=0.0.0.0:11434`
- **Result**: User process binds to 11436, systemd service fails, socat proxy targets wrong port
- **Fix Applied**: Consolidated drop-ins, enabled systemd service on 11434, updated socat to target 11434

### 2. Ollama Systemd Service Inactive - FIXED
- **Problem**: ollama.service disabled and dead (exit-code)
- **Root Cause**: Conflicting drop-ins + User process already holding port + SSH tunnel blocking 11434
- **Fix Applied**: 
  1. Removed all conflicting drop-ins
  2. Created unified drop-in: `/etc/systemd/system/ollama.service.d/10-unified.conf`
  3. Changed service user from `ollama` to `schattenmacher` (for model directory access)
  4. Enabled and started ollama.service
  5. Stopped user process

### 3. SSH Tunnel Blocking Port 11434 - FIXED
- **Problem**: `ollama-reverse-tunnel.service` creates forward tunnel `-L 11434:127.0.0.1:11434 ryzen-recovery`
- **Fix Applied**: Stopped and disabled service, removed unit file

### 4. CUDA Toolkit Not Installed - UNCHANGED
- **Problem**: `nvcc` not found, only CUDA runtime 13.0 via driver
- **Impact**: Cannot compile llama.cpp with CUDA support
- **Status**: Documented, not fixed (requires package installation)

### 5. Missing Model Manifests - UNCHANGED
- **Problem**: Only 3 of 29 models have valid manifests in registry
- **Cause**: Models copied without manifest metadata
- **Impact**: Only 3 models visible via API
- **Status**: Documented, requires re-pull or manifest regeneration
