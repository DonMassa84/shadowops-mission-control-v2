## Root Causes Identified

### 1. Ollama Port Mismatch (CRITICAL)
- **Problem**: Multiple conflicting configurations for Ollama port
  - User .bashrc: `OLLAMA_HOST=0.0.0.0:11434`
  - Systemd drop-in shadow-i7.conf: `OLLAMA_HOST=127.0.0.1:11434`
  - Systemd drop-in nemo-gpu.conf: `OLLAMA_HOST=0.0.0.0:11434`
  - Systemd drop-in 90-env.conf: `OLLAMA_HOST=0.0.0.0:11434`
- **Result**: User process binds to 11436 (unknown why), systemd service fails, socat proxy targets wrong port
- **Impact**: Tailnet API returns 403/empty, healthcheck shows empty models

### 2. Ollama Systemd Service Inactive
- **Problem**: ollama.service is disabled and dead (exit-code)
- **Root Cause**: Conflicting drop-ins + User process already holding port
- **Impact**: No managed Ollama service, relies on user auto-login

### 3. CUDA Toolkit Not Installed
- **Problem**: `nvcc` not found, only CUDA runtime 13.0 via driver
- **Impact**: Cannot compile llama.cpp with CUDA support

### 4. ssh Tunnel Occupies 11434
- **Problem**: SSH tunnel from Ryzen binds 127.0.0.1:11434
- **Impact**: Blocks systemd Ollama from binding to configured port
